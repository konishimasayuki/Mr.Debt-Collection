# 移行

移行は2026年8月の予定。**過去の入金実績は復元しない**方針で決まっている。

## 元データの形

Google スプレッドシート1冊。2026年2月から7月まで、月ごとにシートが分かれている。
各シートは「その月に納車した契約の一覧」であり、入金の記録ではない。

列は、氏名 / 連絡先 / 車両 / 支払総額 / 手数料(25%) / 買取額 / 毎月額 / ボーナス月 /
支払い開始日 / 回数 / 納車日 / 納車月 / 入金状況(チェックボックス) / メモ。

| シート | 件数 | 毎月額合計 | 支払総額 |
|---|---|---|---|
| 2月 | 9(+所在不明1) | 378,443 | 18,165,264 |
| 3月 | 7 | 294,324 | 14,615,552 |
| 4月 | 7 | 416,256 | 20,700,288 |
| 5月 | 7 | 351,353 | 19,904,944 |
| 6月 | 8 | 321,765 | 16,804,720 |
| 7月 | 16 | 709,860 | 35,833,286 |
| 合計 | 54(+1) | 2,472,001 | 126,024,054 |

明細から確認できたのは54件・毎月額 2,442,001円・支払総額 124,584,054円。
差分の1件は下記のとおり所在不明。

## 落とし穴

**2月シートに、明細に見当たらない契約が1件ある。**
合計欄が明細より毎月30,000円・支払総額1,440,000円だけ多い。行番号も2が飛んでいる。
非表示の行があるか、削除した契約を合計式が拾っているかのどちらか。
前者なら **48回払い・毎月30,000円の債権が誰にも確認されていない**。移行前に必ず確認する。

**ボーナス月の欄の意味が、5月シートから反転している。**
支払総額から逆算すると次のとおり。

- 3月・4月シート … その月に払う**合計額**(例: 藤田さん 76,500 = 毎月46,500 + 加算30,000)
- 5月・6月・7月シート … **加算額だけ**(例: 熊上さん 100,000 → 実際の請求は 158,411)

同じ列に2つの意味が混在している。5月シートを3月シートと同じ感覚で読むと請求額を間違える。

**書式が6種類ある。** `(8・12)` `76500（5.29)` `５・１１ 50000` `年間 ６万` など。
月と金額を別の欄に分けて取り込むこと。

**支払日が27日でない契約がある。** メモに「毎月1日」「毎月6日」とある。恒久ルール。
一方、「07/25」「7/31」「7月10日」はその回限りの約束であり、意味が違う。同じ欄に混在している。

**表記ゆれ。** 4月・5月シートだけ氏名が「様」付き。2月シートの「梅木光治藤田カナ」は
1契約か2人分か不明(要確認)。

**「回収」が3件。** メモ欄に2文字あるだけで、残債の扱いは記録されていない。合計 5,712,145円。

## 取り込み手順

1. 全シートを1つの契約テーブルに転記する。連絡先は権限を分けて格納する
2. **検算1**: 手数料 = 支払総額 × 0.25。54件すべて一致することを確認済み
3. **検算2**: 毎月額 × 48 + ボーナス総額 = 支払総額。ボーナス総額から
   1回あたりの加算額と回数を逆算し、記載された金額が「加算額」か「合計額」かを自動判定する
4. **検算3**: シートの合計欄と、転記した明細の合計を突き合わせる。
   3〜7月の5シートは一致。2月のみ差分1件(上記)
5. 検算を通らなかったものだけを人に出す。全件を目視で確認しない
6. 契約から48回分の支払予定を生成する。ボーナス加算は含めない(ADR-002)

この手順で、54件のうち人が確認すべきものは3件に絞り込めた。

## 要確認の3件

| 契約 | 内容 | 判明していること |
|---|---|---|
| 藤田 浩平 | `76500（5.29)` の「29」が月として読めない | 1回30,000円 × 年2回 × 4年 = 240,000円は確定。**何月かが不明** |
| 渡邉 渉 | `年間 ６万` | 年1回6万円 × 4年 = 240,000円は確定。**何月かが不明** |
| 吉武 慎治 | 6円だけ合わない | 丸め誤差とみられる。**そのまま表示する。辻褄を合わせる処理を入れない** |

## 開始時に必要な作業

過去の実績はこの資料から復元できない。入金状況のチェックボックスが契約に1つしかないため。

開始時に一度だけ、**54件それぞれが何回目まで入金済みか**を銀行明細で確認して初期値を入れる。
これをやらないと初日から未収額が正しく出ない。54件なので1日仕事。

累計差額の初期値も同時に入れる。既知のものは山本一馬さんの「残金10,000」。
