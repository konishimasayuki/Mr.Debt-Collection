# 仕様

判断の理由は `adr.md` にある。ここには「何を作るか」だけを書く。
迷ったら `nyukin-daicho.html`(モック)を開くこと。文章より正確に動作を示している。

## 用語

画面に出す言葉と、内部で使う言葉を分ける。左を画面に出し、右はコードの中だけで使う。

| 画面に出す | 内部 | 備考 |
|---|---|---|
| 入金あり / 記録する | 消込 | 「消込」は画面に出さない |
| 何の分か | 充当・内訳 | |
| 未収 | 債権・売掛金 | |
| 支払い予定表 | 償還予定表・アモチ表 | |
| これまでの記録 | 事象・監査ログ | |
| ようす | ステータス | |
| (画面に出さない) | 名寄せ | 裏で処理する |

## データモデル

### 契約 (contract)

| 項目 | 型 | 備考 |
|---|---|---|
| id | | |
| 氏名 / 連絡先 / 車両 | | 連絡先は権限を分ける対象 |
| 買取額 / 手数料 / 支払総額 | 金額 | 手数料は支払総額の25%固定。登録時に検算する |
| 毎月額 / 回数 | | 回数は現状すべて48 |
| 支払日 | 1〜31 | 原則27。契約ごとの例外を認める |
| 支払開始日 | 日付 | 原則、納車の翌月27日 |
| ボーナス月 | 月の配列 | **金額と別の欄で持つ。文字列で持たない** |
| ボーナス加算額 | 金額 | 1回あたり |
| ボーナス見込み残 | 金額 | 支払総額 − 毎月額×回数。減るのは入金があったときだけ |
| 累計差額 | 金額 | マイナスが不足、プラスが前受 |
| 差額の扱い | 列挙 | 未定 / 最終回 / 均等 / 別途請求 |
| 状態 | 列挙 | 通常 / 別あつかい(値は今後増やす。ADR-008) |
| 納車日 / 納車月 | | |

### 支払予定 (schedule)

契約登録時に48行を自動生成する。`契約ID, 回次, 支払期日, 予定額, 状態`。
予定額は毎月額のみ。ボーナス加算は含めない(ADR-002)。

### 入金 (payment)

`日付, 金額, 受け取り方(振込/現金/その他), 領収書番号, 記録者, 取込元`。
現金は受領日と預入日を別に持つ。手元現金の残高が合うことを月次で別の人が照合する。

### 充当 (allocation)

`入金ID, 予定ID, 充当額, 区分`。区分は 元本 / 手数料 / 遅延損害金 / 値引 / 相殺 / 前受 / ボーナス。
**入金に予定IDを1本だけ持たせてはいけない**(ADR-003)。

### 事象 (event)

`契約ID, 回次, 日時, 記録者, 種類, 本文, メモ`。追記のみ(ADR-005)。
種類は 請求 / 入金 / 遅れ / 未収 / 差額 / 約束 / 不履行 / 回収 / ボーナス / メモ / 取消。

### 名寄せ辞書 (payer_alias)

`正規化した振込依頼人名 → 契約ID`。一度人が紐付けたら永続化する。
正規化は、半角と全角カナの統一、法人格の除去(`カ)` `(カ` `カブシキガイシャ`)、記号と空白の除去。

**同姓が実在する。** 山田が2名、斎藤と齊藤がカナで同一になる。金額と過去の履歴で判断する。

### 約束 (promise)

`契約ID, 聞いた日, 約束の日, 金額, 聞いた人, メモ`。
**予定日を書き換えるのではなく独立して持つ。** 書き換えると滞納していた事実が消える。

## 画面

### 本日の作業

毎朝ここから始まる。**毎日やること以外を置かない。**

1. 本日の入金を確かめる
2. 遅れている方に連絡する
3. 誰の入金か分からないものを片づける
4. 後日の約束を確かめる

右側に「溜まっているもの」を放置日数の長い順に表示する。件数ではなく日数で並べる。
督促は「何件あるか」より「どれが一番ほったらかしか」で動く。

数字は必ず入口にする。押すと台帳の該当区分へ移動する。行き止まりの数字を置かない。

### 懸案

今日でなくてよい仕事。種類ごとに、件数・金額・**なぜ放っておけないかの1行**を添える。
行を押すとその場で開き、その懸案に対する選択肢を出す。**台帳の消し込み画面へ飛ばさない。**

現在の内訳: 預かった現金の預入 / 差額の扱い / 回収の残債 / ボーナス依存 / 完済前の精算。
ルールが未定のもの(回収・ボーナス)は「決まっていません」と赤字で表示し、
できるのはメモを残すことだけにする。仮の選択肢を置かない。

### 台帳

契約ごとの消し込み。行をクリックすると同じ場所で入金欄が開く。画面遷移しない。
消し込むと行は消えず、藍の二重線(見消し線)が引かれて残る。

行を開いたときの配置は、ラベル76pxの右に操作を揃える。受け取り方・金額・メモ・記録するボタンが
同じ縦線から始まること。金額の選択肢は数が変わっても押す位置がずれないよう幅を固定する。

### 入金表

契約者 × 直近12ヶ月のマトリクス。セルは 済 / 遅 / 未 / 差 / 期日が来ている / これから / 契約前。
色だけに頼らず1文字を入れる(印刷と色覚への配慮)。既定の並びは滞りの多い順。
名前の列と見出し行を固定する。

## 判定ルール

| ルール | 現在値 | 根拠 |
|---|---|---|
| 差額の督促しきい値 | 1,000円 | 振込手数料ぶんを除外するため。実績を見て調整(ADR-007) |
| 完済前の精算の案内 | 残り12回 | 分割の相談と引き揚げ判断に必要な時間。金額のしきい値は適用しない |
| ボーナス依存が重い | 毎月額の10回分 | 残り回数ではなく比率で見る。契約直後でも危険が見えるため |
| 手数料 | 支払総額の25% | 全54件で一致。登録時に検算する |
| 元本と手数料の按分 | 75:25 | 定率。各回の按分に使用 |

## 状態の判定

日々の消し込みに出す条件は次の通り。**回収など「別あつかい」の契約は、遅れにも本日にも出さない。**

- 遅れ … 期日 < 本日、未入金
- 本日 … 期日 = 本日
- 約束 … 約束の日 ≦ 本日、未入金
- これから … 期日 > 本日
- 別あつかい … 状態が通常でない(ADR-008)
