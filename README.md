# 入金管理台帳

自社割賦(車を自社の分割払いで売る)の入金を管理する台帳。
電話を受ける担当者が使い、経営者の質問にもここで答える。

- **使い方** … `docs/取り扱い書.md`（読む用は `docs/取り扱い書.html`）
- **引き継ぎ** … `docs/引き継ぎ設計書.md`
- **データの持ち方** … `docs/データ保存設計.md`
- **公開の手順** … `DEPLOY.md`
- **検査の走らせ方** … `tests/README.md`

## 画面

ヘッダーに8つのタブ。

| タブ | すること |
|---|---|
| **ダッシュボード** | 月ごとの予定回収額と、まだ入っていない額。期日が今日以前の回だけを数える |
| **顧客一覧** | あいうえお順(索引つき)。残債金額の総額を先頭に出す。右上から新規顧客登録と、よみの一括入力 |
| **入金登録** | 上に CSV・銀行からの取り込み、下に手動入金 |
| **入金履歴** | 当日を最新に降順。直せる。顧客検索つき |
| **未入金** | 期日までに入金できていない顧客をあいうえお順で。督促の記録と、その場での手動入金 |
| **完済/引き上げ** | 終わった取引。引き上げた方と払い終わった方を色で分ける |
| **設定** | 債権会社・銀行口座の登録、入金の無い顧客の削除、動作を試すための顧客 |
| **デバッグ依頼** | 使っていて困ったことを、画面から画像つきで出す |

顧客一覧の行を押すと**顧客ページ**が開く。左7割が月カレンダー、右3割が支払いの記録。
カレンダーには固定の支払日が出ていて、日付を押すとその日に入金約束を足せる
(約束日・何時まで/終日・どの回ぶんいくら・メモ)。顧客についてのメモも持てる。

支払いの記録は、回を押すと下が開く。

| 押した回 | できること |
|---|---|
| どの回でも | その回にメモを足す |
| ボーナスの回 | その賞与を別の月へ移す |
| まだ入金の無い回 | **その回から先の金額を変える**(理由の記入が必須) |
| 入金の行(ボーナス払いの方) | その振り込みを月額とボーナスに割り当て直す |

## 決めごと

- **期日は動かない。** 入金約束をいくつ足しても、契約で決まった支払日は変わらない
- **1回ぶんに約束を何件でも足せる。** 「3日後に半分、5日後に残り」が日常のため
- **1件の入金を複数の回に按分できる。** まとめ払いも分割入金も同じ仕組みで扱う
- **古い回から順に埋める。** 「1回目は未入金なのに3回目は入金済み」を作らない
- **満額に届くまでは「一部入金」。** 届いてはじめて「入金済み」
- **ボーナスの回に入れてよいのは、人がボーナスと決めた入金だけ。**
  自動では当てない(同じ日に月額とボーナスが並ぶと、金額の大きいほうが先に埋まるため)
- **賞与は、契約の最終回より後になっても回数ぶん作る。**
  入る月が足りないからと落とすと、払う約束をしたお金が台帳から消える
- **月々の金額と支払回数は顧客編集では変えられない。**
  これからの金額は、支払いの記録の未払いの回から変える(払い終えた回は動かない)
- **入金が1件でもある顧客は消せない。** 1円でも受け取っていれば、守るべきお金の跡がある
- **手動入金は理由(メモ)が必須で、履歴では行の背景を変える**
- **記録(`event`)は消せない。** 訂正は「取消」を足す。データベース側でも禁止している
- **顧客検索は かな / 全角カナ / 半角カナ / 半角英字 / 全角英字 のどれでも当たる**
- **スマホ・iPad のホーム画面に置ける。** 電波が無いと開くところまで
  （台帳の中身はサーバーにある）

## 構成

```
index.html, src/        画面(React 19 + Vite 8)
  src/App.jsx           タブの切り替えと全体の状態(ルーターは使わない)
  src/api.js            サーバーを呼ぶ窓口(画面からは必ずここを通す)
  src/pages/            画面ごとの部品
  src/components/ui.jsx 共通の部品(Modal・Text・Select・Note など)
  src/styles.css        見た目(すべてここ。CSSフレームワークは使わない)
public/                 アイコン・manifest・受け皿(sw.js)
tools/icons.mjs         アイコンを描いて撮る（node tools/icons.mjs）
api/*.js                Vercel の関数(ESM / Node 22)。1ファイル＝1エンドポイント
api/_*.js               共通部品(スキーマ・DB・正規化・CSV解析・銀行の差し込み口)
tests/                  自動検査(APIと画面の両方)
docs/                   取り扱い書・引き継ぎ設計書・データ保存設計
DEPLOY.md               Vercel での公開手順と初回の作業
```

**変数名も関数名も日本語で書く。** 業務の言葉とコードの言葉を一致させ、
業務に詳しい人が読めるようにするため。新しく書くときもこの書き方にそろえる。

## 手元で動かす

```bash
npm install

# 手元のデータベース
pg_ctlcluster 16 main start
createdb -U postgres -h /var/run/postgresql v2

npm run build
node tests/server.mjs      # http://localhost:4321
```

ログインは `a` / `a`（環境変数を入れていないとき）。

`npm run dev` は画面だけを立てる。**API も含めて試すときは `tests/server.mjs`**（本番と同じ形）。
API を直したら立て直すこと。

## 検査

```bash
bash tests/run.sh
```

事前に `tests/server.mjs` を立てておく。詳しくは `tests/README.md`。

## 使いはじめ

`DEPLOY.md` を読むこと。環境変数を入れ、`POST /api/setup` でテーブルと
既存データを入れてから、設定タブで債権会社を登録する。

**テーブルの用意と載せ替えは画面に置いていない。** 移行のときに一度使うだけで、
日々使う人の設定タブに置いておくと誤って押されるため。

## 出し方

`main` に入ると Vercel が自動で本番へ出す。出す前に

- [ ] `npm run build` が通る
- [ ] `bash tests/run.sh` がすべて通る
- [ ] スキーマを変えたなら `api/_schema.js` に `ALTER TABLE` も足した
      （**列を足す文は、その列を使う索引より前に置く**）
- [ ] 画面を直したなら、スマートフォンの幅(390px)でも見た
- [ ] 取り扱い書(`docs/取り扱い書.md` と `.html` の両方)を直した
